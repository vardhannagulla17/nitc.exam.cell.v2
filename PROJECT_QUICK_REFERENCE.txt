🗄️ DATABASE SCHEMA (5 TABLES)
================================================================================
1. users → Authentication (email, password_hash, role, is_approved)
2. semesters → Exam periods (academic_year, semester_type, degree_level)
3. students → Enrollment data (roll_no, name, course_code, semester_id)
4. absentees → Absent tracking (roll_no, course_code, exam_date, status, marked_by)
5. exam_timetable → Exam schedule (course_code, exam_date, venue)

Storage Buckets:
  pending_absentee → Staff submissions awaiting review
  approved_absentee → Admin-approved records
  rejected_absentee → Rejected records (audit trail)

🔐 AUTHENTICATION FLOW
================================================================================
Registration: Email → OTP → Create (is_approved=false) → Admin approves
Login: Email + Password → Verify hash → Create session → Redirect dashboard
Session: Encrypted cookie, expires 24hrs, stores user_id/role/username
Security: Bcrypt hashing, session validation on every route

🐛 BUG FIX STORY (Show Problem-Solving)
================================================================================
Problem: "Preview All" button opens same page in new tab (not preview)
Root Cause: Browser doesn't handle POST + formtarget="_blank" reliably
Investigation: Checked route handling, tested POST data arrival
Solution: JavaScript dynamic form creation → submit → cleanup
Result: Preview now works perfectly in new tab

Code:
  function previewConsolidated() {
    const form = document.createElement('form');
    form.method = 'POST';
    form.action = '/admin/absentees';
    form.target = '_blank';
    const input = document.createElement('input');
    input.name = 'action';
    input.value = 'preview_consolidated';
    form.appendChild(input);
    document.body.appendChild(form);
    form.submit();
    document.body.removeChild(form);
  }

💡 INTERVIEW QUESTIONS & ANSWERS
================================================================================

Q: Why Flask over Django?
A: "Flask's lightweight and flexible. Didn't need Django's ORM since using
   Supabase. Flask allowed rapid development with full control over structure."

Q: How does authentication work?
A: "Session-based. Login → verify bcrypt hash → store in encrypted session
   cookie → validate on each request. Sessions expire after 24 hours."

Q: Most challenging part?
A: "Absentee approval workflow with bucket synchronization, bulk operations
   with real-time UI updates via AJAX, and ensuring data consistency."

Q: How would you scale?
A: "1. Separate frontend (React/Next.js) 2. Redis for sessions 3. Connection
   pooling 4. CDN for static files 5. Load balancer 6. Background job queues"

Q: Security concerns?
A: "Implemented hashing, auth, RBAC, input validation, file checks. Production
   needs: HTTPS, CSRF tokens, rate limiting, 2FA, audit logs, pen testing."

Q: What would you change?
A: "React frontend for better state management, microservices architecture,
   comprehensive test suite, CI/CD pipeline, proper logging/monitoring."
