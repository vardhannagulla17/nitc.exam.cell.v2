================================================================================

Project Name: NITC Exam Cell Attendance Management System
Institution: National Institute of Technology Calicut (NITC)
Purpose: Automate and streamline the process of managing student attendance

PROBLEM IT SOLVES:
------------------
Before: 
- Staff manually created attendance sheets in Excel/Word

3. PROJECT ARCHITECTURE
================================================================================

ARCHITECTURE PATTERN: Monolithic MVC (Model-View-Controller)
-----------------------------------------------------------

[CLIENT BROWSER]
       ↓↑ HTTP Requests/Responses
[FLASK APPLICATION]
       ├── Routes (Controller) - app.py, app/routes.py
       ├── Models (Data Logic) - app/models.py, app/database.py
       ├── Views (Templates) - templates/*.html
       └── Utilities - helpers/, app/attendance.py
           ↓↑
[SUPABASE CLOUD]
       ├── PostgreSQL Database (users, students, absentees, etc.)
       └── Storage Buckets (pending_absentee, approved_absentee)

LAYERED ARCHITECTURE:
--------------------
Layer 1: PRESENTATION LAYER (Frontend)
   - HTML templates with Jinja2
   - CSS styling
   - JavaScript for interactivity
   - User interface components

Layer 2: APPLICATION LAYER (Backend Logic)
   - Flask routes (URL handlers)
   - Business logic
   - Form processing
   - Session management
   - Authentication/Authorization

Layer 3: DATA ACCESS LAYER
   - Supabase client (supabase_client.py)
   - Database operations (CRUD)
   - ORM-like operations using Supabase Python SDK
   - Query building

Layer 4: DATA STORAGE LAYER
   - Supabase PostgreSQL database
   - Supabase Storage buckets
   - Row-level security policies

Layer 5: EXTERNAL SERVICES
   - None currently (could add email, SMS, etc.)

REQUEST FLOW:
-------------
1. User makes HTTP request (e.g., GET /dashboard)
2. Flask routing matches URL to handler function
3. Handler checks authentication (session)
4. Handler queries database via Supabase client
5. Data is processed/formatted
6. Template is rendered with data
7. HTML response sent back to browser
8. Browser renders the page

SUPABASE OVERVIEW:
------------------
Supabase = Open-source Firebase alternative
Components used in this project:
1. PostgreSQL Database (primary data store)
2. Storage Buckets (file storage)
3. Row Level Security (RLS) policies
4. Auto-generated REST API

CONNECTION SETUP:
-----------------
File: supabase_client.py

```python
from supabase import create_client, Client

SUPABASE_URL = os.environ.get("SUPABASE_URL")
SUPABASE_KEY = os.environ.get("SUPABASE_ANON_KEY")

supabase = create_client(SUPABASE_URL, SUPABASE_KEY)
```

DATABASE SCHEMA:
----------------

TABLE 1: users
--------------
Purpose: Store user accounts (admin and staff)

Columns:
- id (BIGSERIAL PRIMARY KEY)          # Auto-incrementing unique ID
- email (TEXT UNIQUE NOT NULL)        # User's email (login identifier)
- full_name (TEXT NOT NULL)           # Display name
- password_hash (TEXT NOT NULL)       # Bcrypt hashed password
- role (TEXT DEFAULT 'staff')         # 'admin' or 'staff'
- is_approved (BOOLEAN DEFAULT FALSE) # Admin approval required
- is_active (BOOLEAN DEFAULT TRUE)    # Enabled/disabled status
- created_at (TIMESTAMP DEFAULT NOW())
- approved_at (TIMESTAMP)
- approved_by (TEXT)                  # Admin who approved

Indexes:
- idx_users_email (on email)
- idx_users_is_approved (on is_approved)

Usage:
- Login authentication
- Role-based access control
- User management by admin

ROW LEVEL SECURITY (RLS):
--------------------------
All tables have RLS enabled with policies that allow service role to access.
This ensures data security at the database level.

Policy examples from schema:
```sql
CREATE POLICY "Enable all for service role" ON users
    FOR ALL 
    USING (true)
    WITH CHECK (true);
```

In production, you'd have more granular policies like:
- Users can only see their own data
- Admins can see all data
- Staff can only update their own records

6. AUTHENTICATION & AUTHORIZATION SYSTEM
================================================================================

AUTHENTICATION FLOW:
--------------------

1. REGISTRATION (Staff Self-Registration):
   Step 1: User fills registration form (register.html)
           - Email (must be @nitc.ac.in)
           - Full name
           - Password
   
   Step 2: Form submits to /register route
   
   Step 3: Backend validates input:
           - Email format check
           - Password strength
           - Check if email already exists
   
   Step 4: Generate OTP (6-digit random number)
           - Store in session
           - Send via email (if SMTP configured)
   
   Step 5: Redirect to OTP verification page
   
   Step 6: User enters OTP
   
   Step 7: If OTP matches:
           - Hash password with bcrypt
           - Create user record with is_approved=False
           - Redirect to waiting page
   
   Step 8: Admin reviews and approves user

2. LOGIN:
   Step 1: User enters username (email) and password (login.html)
   
   Step 2: Form submits to /login route
   
   Step 3: Backend validates:
           ```python
           # Find user by email
           user = supabase.table('users')\
               .select('*')\
               .eq('email', username)\
               .execute()
           
           # Verify password
           from werkzeug.security import check_password_hash
           if check_password_hash(user['password_hash'], password):
               # Password correct
           ```
   
   Step 4: Check if user is approved and active
   
   Step 5: If valid, create session:
           ```python
           session['user_id'] = user['id']
           session['username'] = user['email']
           session['role'] = user['role']
           session['full_name'] = user['full_name']
           session.permanent = True
           ```
   
   Step 6: Redirect to dashboard

3. SESSION MANAGEMENT:
   - Flask sessions (server-side)
   - Secret key for encryption
   - Persistent for 24 hours
   - Stored in browser cookie (encrypted)

4. LOGOUT:
   ```python
   @app.route('/logout')
   def logout():
       session.clear()
       return redirect(url_for('login'))
   ```

AUTHORIZATION (Role-Based Access Control):
-------------------------------------------

DECORATOR PATTERN:
```python
def require_login(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if 'user_id' not in session:
            return redirect(url_for('login'))
        return f(*args, **kwargs)
    return decorated_function

def require_admin(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if session.get('role') != 'admin':
            flash('Access denied. Admins only.')
            return redirect(url_for('dashboard'))
        return f(*args, **kwargs)
    return decorated_function
```

IMPLEMENTATION IN ROUTES:
```python
@app.route('/admin/users')
def admin_users():
    # Check authentication
    if 'user_id' not in session:
        return redirect(url_for('login'))
    
    # Check authorization
    if session.get('role') != 'admin':
        flash('Access denied. Admins only.')
        return redirect(url_for('dashboard'))
    
    # Proceed with admin-only logic
    users = get_all_users()
    return render_template('admin_users.html', users=users)
```

```python
def generate_attendance_sheet(course_code, exam_date, semester_id, preview=False):
    # 1. Get all students for this course
    students = supabase.table('students')\
        .select('*')\
        .eq('semester_id', semester_id)\
        .eq('course_code', course_code)\
        .execute()
    
    # 2. Sort by roll number
    students = sorted(students.data, key=lambda x: x['roll_no'])
    
    # 3. Generate HTML table
    html = f"""
    <!DOCTYPE html>
    <html>
    <head>
        <title>Attendance Sheet - {course_code}</title>
        <style>
            table {{ border-collapse: collapse; width: 100%; }}
            th, td {{ border: 1px solid black; padding: 8px; }}
            th {{ background-color: #f2f2f2; }}
        </style>
    </head>
    <body>
        <h1>{course_code} - {students[0]['course_title']}</h1>
        <h2>Exam Date: {exam_date}</h2>
        <table>
            <thead>
                <tr>
                    <th>S.No</th>
                    <th>Roll No</th>
                    <th>Name</th>
                    <th>Signature</th>
                    <th>Bio-break Out</th>
                    <th>Bio-break In</th>
                    <th>Additional Sheet No.</th>
                </tr>
            </thead>
            <tbody>
    """
    
    # 4. Add student rows
    for i, student in enumerate(students, 1):
        html += f"""
                <tr>
                    <td>{i}</td>
                    <td>{student['roll_no']}</td>
                    <td>{student['name']}</td>
                    <td>&nbsp;</td>
                    <td>&nbsp;</td>
                    <td>&nbsp;</td>
                    <td>&nbsp;</td>
                </tr>
        """
    
    html += """
            </tbody>
        </table>
    </body>
    </html>
    """
    
    # 5. Return HTML (for preview) or save to file (for download)
    if preview:
        return html
    else:
        # Save to downloads folder
        filename = f"Attendance_{course_code}_{exam_date}.html"
        filepath = os.path.join(DOWNLOAD_FOLDER, filename)
        with open(filepath, 'w', encoding='utf-8') as f:
            f.write(html)
        return filepath
```

11. SECURITY MEASURES
================================================================================

1. PASSWORD SECURITY:
   - Bcrypt hashing (via werkzeug.security)
   - Salted hashing (unique salt per password)
   - Never store plain passwords
   - Hash comparison using check_password_hash()

2. SESSION SECURITY:
   - Encrypted session cookies
   - Secret key for signing
   - Expires after 24 hours
   - Server-side session data

3. INPUT VALIDATION:
   - File type checking (allowed_file())
   - Filename sanitization (secure_filename())
   - SQL injection prevention (Supabase parameterized queries)
   - XSS prevention (Jinja2 auto-escaping)

4. AUTHENTICATION:
   - Session-based authentication
   - Login required decorators
   - Role-based access control

5. AUTHORIZATION:
   - User role checking (admin vs staff)
   - Feature access restriction
   - Resource ownership validation

6. FILE UPLOAD SECURITY:
   - File size limit (16MB)
   - Extension whitelist (.xlsx, .xls only)
   - Secure filename handling
   - Temporary storage in controlled directory

7. DATABASE SECURITY:
   - Supabase Row Level Security (RLS)
   - Service role key for backend (not exposed)
   - Parameterized queries (no raw SQL with user input)

8. CORS & CSRF:
   - Same-origin policy
   - No CSRF token needed (same-origin requests)
   - Flash messages prevent replay

9. ERROR HANDLING:
   - Generic error messages to users
   - Detailed errors only in development

10. ENVIRONMENT VARIABLES:
    - Secret keys in .env (not in git)

    - Production/development separation

PATTERN 1: Route Handler Template

```python
@app.route('/endpoint', methods=['GET', 'POST'])
def handler_function():
    # 1. Authentication check
    if 'user_id' not in session:
        return redirect(url_for('login'))
    
    # 2. Authorization check (if needed)
    if session.get('role') != 'admin':
        flash('Access denied')
        return redirect(url_for('dashboard'))
    
    # 3. GET request - display form
    if request.method == 'GET':
        # Fetch data
        data = fetch_data_from_db()
        # Render template
        return render_template('template.html', data=data)
    
    # 4. POST request - process form
    if request.method == 'POST':
        # Get form data
        value = request.form.get('field_name')
        
        # Validate input
        if not value:
            flash('Field required', 'error')
            return redirect(request.url)
        
        # Process data
        try:
            result = process_data(value)
            flash('Success!', 'success')
            return redirect(url_for('success_page'))
        except Exception as e:
            flash(f'Error: {str(e)}', 'error')
            return redirect(request.url)
```
